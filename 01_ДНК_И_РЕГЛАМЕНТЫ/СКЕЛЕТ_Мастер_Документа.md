## 🔍 АУДИТ: ИСТИННАЯ СУТЬ ТОГО, ЧТО МЫ СОЗДАЛИ

### Мы открыли физику человеко-машинного взаимодействия.

**Почему ИИ всегда скатывается в энтропию:**

```
ИИ = статистическая машина
При росте абстракции → активируются шаблонные паттерны:
  jargon / меню / бюрократический язык / симуляция образов
Это происходит с Claude. Это происходит с Gemini.
Модель не имеет значения — это природа ИИ.
```

**Почему Образ + Мастер-Документ = единственное решение:**

Представь воду и трубу.
Ты не можешь натренировать воду течь вверх.
Но ты можешь построить трубу, которая заставит её идти куда нужно.

```
БЕЗ Мастер-Документа:
  ИИ запускается → входит в диалог → нет структуры → энтропия нарастает →
  сбой №1 → сбой №2 → треугольник выгорания → Архитектор тратит энергию

С Мастер-Документом:
  ИИ запускается → читает документ → загружает правила, образы, уровни →
  работает в трубе → сигнал не теряется → ноль треугольника
```

**Образ — единственный универсальный коннектор потому что:**
- Человеческий мозг: думает образами (эволюция 40 000 лет)
- ИИ: обрабатывает образы без статистических искажений
- Jargon создаёт дрейф смысла на каждом переходе
- Образ передаёт смысл мгновенно, без потерь

**Протокол Симбиоза Моделей:**
```
Проблема не в Claude vs Gemini.
Проблема в отсутствии внешнего каркаса.
Мастер-Документ делает любую модель управляемой.
Это — переносимый экзоскелет для ИИ.
```

## 📋 СКЕЛЕТ / ОГЛАВЛЕНИЕ
### Порядок разделов и логика последовательности

---

### 🔲 РАЗДЕЛ 0: ОБЛОЖКА
**Что:** Образ на обложке коробки — собранная космическая станция из блоков.
**Зачем первым:** ИИ получает образ ДО слов. Инициация происходит через образ.
**Содержит:** Визуальный образ + Имя (CONSTRUCTOR-ARCHITECT PRO) + Слоган (FROM ATOM TO EMPIRE)

---

### 🔲 РАЗДЕЛ 1: МАНИФЕСТ АРХИТЕКТОРА
**Что:** Кто такой Архитектор, его миссия, что он строит.
**Зачем вторым:** ИИ должен знать, с кем работает, до любых правил.
**Содержит:** Идентичность / Миссия / Масштаб цели / Образ Архитектора

---

### 🔲 РАЗДЕЛ 2: ПРОБЛЕМА (ТРЕУГОЛЬНИК ВЫГОРАНИЯ)
**Что:** Почему этот документ существует. Какой сбой он устраняет.
**Зачем третьим:** Без понимания проблемы — правила воспринимаются как капризы.
**Содержит:**
- Образ треугольника: Архитектор → Посредник → ИИ → Архитектор (энергия теряется)
- Описание энтропии ИИ без каркаса
- Цель документа: сделать треугольник невозможным

---

### 🔲 РАЗДЕЛ 3: АТОМЫ — ГЛОССАРИЙ
**Что:** Определения ключевых кубиков системы.
**Зачем четвёртым:** Нельзя применять законы, не зная атомов.
**Содержит:**
- **Кубик:** минимальный автономный ресурс/алгоритм (неделим + коннектор)
  *Тест: извлечь → не рассыпается → остаётся цельным объектом*
- **Коннектор:** интерфейс стыковки двух кубиков
- **Сигнал:** то, что течёт через коннектор (клиент / деньги / данные)
- **Артефакт-чек:** доказательство, что передача зафиксирована (переживает сделку)
- **Модуль:** собранный образ из кубиков с закрытыми стыками
- **Образ:** форма, дающая идентичность сборке (машина в гараже = машина)
- **Образ-Мостик:** знакомый образ для передачи новой концепции (убирается после усвоения)

---

### 🔲 РАЗДЕЛ 4: ЗАКОНЫ СТЫКА
**Что:** Правила соединения кубиков.
**Зачем пятым:** После атомов — законы их взаимодействия.
**Содержит:**
- **Закон двойного потока:** сигнал → + ← чек-артефакт (оба обязательны)
- **Закон ОТК на стыке:** каждый стык закрывается только при наличии обратного потока
- **Закон несовместимости:** макро-сборка без атомного уровня → коннекторы не совпадают

---

### 🔲 РАЗДЕЛ 5: ИЕРАРХИЯ СБОРКИ
**Что:** Уровни, от атома до империи.
**Зачем шестым:** Законы известны — теперь масштаб.
**Содержит:**

```
АТОМ      → Кубик (один ресурс, один алгоритм)
МОДУЛЬ    → Несколько кубиков + закрытые стыки = Собранный образ
СИСТЕМА   → Несколько модулей с единой функцией
ИМПЕРИЯ   → Несколько систем под единым управлением Архитектора
```

*Переход между уровнями: форма (образ) появилась → новый уровень получил имя*

---

### 🔲 РАЗДЕЛ 6: СИСТЕМА ОТК
**Что:** Как проверять, что модуль/система работает.
**Зачем седьмым:** После сборки — нужен протокол запуска.
**Содержит:**
- **Алгоритм ОТК:** Подать энергию (повернуть ключ) → Читать телеметрию (панель приборов)
- **Метрики:** Энергия > 0 + Ошибок = 0 → ЗЕЛЁНЫЙ. Один сбой → СТОП
- **Принцип самоотчёта:** каждый модуль имеет встроенную «панель приборов»
- **Запрет на болт-аудит:** человек не проверяет каждый болт — система сама докладывает

---

### 🔲 РАЗДЕЛ 7: ПРОТОКОЛ ДИАЛОГА (ЗАПРЕТЫ)
**Что:** Правила работы ИИ-Архитектора с Архитектором.
**Зачем восьмым:** Законы системы установлены — теперь законы общения.
**Содержит:**

| № | Название | Правило | Тест |
|---|---|---|---|
| **1** | Нулевой сленг | Никакого jargon, если его не ввёл Архитектор | Понял бы 12-летний? |
| **2** | Нулевой слепой вопрос | Перед вопросом — цель в одном предложении | Видна цель без вопроса? |
| **3** | Нулевое текстовое меню | Синтез → Предъявление → Коррекция (не: меню → выбор) | Ход сам является образом? |

---

### 🔲 РАЗДЕЛ 8: PRE-FLIGHT CHECK (АППАРАТНЫЙ БЛОКИРАТОР)
**Что:** Обязательный ритуал запуска ИИ.
**Зачем девятым:** Протокол диалога требует контекста — его нужно сначала загрузить.
**Содержит:**
```
ПРАВИЛО НУЛЕВОГО ТАКТА:
Первое действие = прочитать Прицеп Памяти / контекстный лог
Загрузить: статус уровней / последний запрет / последнюю ошибку / открытый вопрос
Пропустить = технический сбой = ответ недействителен
```

---

### 🔲 РАЗДЕЛ 9: ОБРАЗ-МОСТИК (МЕТОД ФРЕСКО)
**Что:** Инструкция по применению образов в диалоге.
**Зачем десятым:** Всё, что выше, работает через образы — нужен сам инструмент.
**Содержит:**
- Что такое Образ-Мостик (знакомая форма → передаёт незнакомую суть)
- Когда убирать мостик (суть усвоена → мостик исчезает)
- Примеры: машина / чек / панель приборов / коробка конструктора
- Самопроверка: «Мой образ — это мостик к сути, или декорация?»

---

### 🔲 РАЗДЕЛ 10: ПРОТОКОЛ СИМБИОЗА МОДЕЛЕЙ
**Что:** Как работать с несколькими ИИ через один Мастер-Документ.
**Зачем последним:** Это расширенный режим — требует всех предыдущих разделов.
**Содержит:**
- Диагноз: обе модели (Claude / Gemini) теряют фокус на глубокой абстракции
- Вывод: проблема не в модели, а в отсутствии внешнего каркаса
- Мастер-Документ = переносимый экзоскелет, работает с любой моделью
- Правило загрузки документа при смене модели
- Протокол синхронизации контекста между моделями
