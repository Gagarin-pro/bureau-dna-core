# 🔧 УМЕНИЕ: ГИБРИДНЫЙ РЕГЛАМЕНТ УПРАВЛЕНИЯ GOOGLE JULES

> ⚡ **СТАНДАРТ БЮРО LEGO-ARCHITECT PRO**:
> 1. **Закон Атомарности (`atomic-batch-executor`)**: Выполнять чтение и запись файлов исключительно параллельными пакетными вызовами (экономия 50% топлива).
> 2. **Закон Сверх-Сжатого Левого Вакуума**: Выгружать развернутые логи и отчеты ИСКЛЮЧИТЕЛЬНО в `РАБОЧИЙ_ДИАЛОГ.md` (ограничение UI до 15 токенов).


Этот модуль содержит единый жесткий регламент взаимодействия с облачным ИИ-агентом Google Jules (модель Gemini 3.1 Pro/Ultra) на всех этапах сборочного цикла, исключая путаницу между консольным CLI и браузерным управлением.

---

## 🧭 1. ФИЗИЧЕСКИЙ ОБРАЗ (АНАЛОГИЯ)
Google Jules — это **«внешняя приглашенная бригада мастеров»** (веб-платформа jules.google.com). 
Мы передаем им чертеж (инструкции ТЗ) в их мастерской через **глаза и руки** (браузер Google Chrome под управлением протокола CDP), а контролируем готовность и забираем готовую деталь (код) с помощью **автоматического погрузчика** (консольная утилита `jules` CLI).

---

## 📋 2. ЕДИНЫЙ ГИБРИДНЫЙ ПРОТОКОЛ

Все операции делятся на три четких этапа, выполняемых строго в указанном порядке:

```
[Этап 1: Передача ТЗ] ➔ Браузер Google Chrome (CDP-протокол на порту 9222)
      ↓
[Этап 2: Контроль готовности] ➔ Терминал CLI (команда jules remote list)
      ↓
[Этап 3: Накат изменений] ➔ Терминал CLI + Временная папка (jules remote pull)
```

---

## ⚡ ЭТАП 1. ПЕРЕДАЧА ТЗ (Через Браузер)

1. Отправка ТЗ и запуск сессий **запрещено** выполнять через `jules new` в консоли из-за частых зависаний и лимитов API.
2. Всегда используйте автоматизацию Chrome CDP на порту `9222` с рабочим профилем КВС.
3. **Алгоритм автоматической отправки:**
   - Запустить Chrome с отладкой:
     `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222 --user-data-dir="/Users/tur/Desktop/notebook_lm_school/chrome_profile" --no-first-run &`
   - Подключиться по WebSocket к активной сессии на `jules.google.com/session/<SESSION_ID>`.
   - Внедрить текст ТЗ в элемент `textarea.input-box` через вызов событий `input` и `change`.
   - Имитировать клик по кнопке отправки или отправку через `KeyboardEvent(Enter)`.

---

## ⚡ ЭТАП 2. МОНИТОРИНГ (Через CLI)

Для проверки готовности регулярно опрашивайте статус сессии с помощью терминального пульта:
```bash
/Users/tur/.npm/_npx/76db0a0f29ffdc9b/node_modules/.bin/jules remote list --session
```
*Ждите перехода статуса целевой сессии из `In Progress` в `Completed`.*

---

## ⚡ ЭТАП 3. НАКАТ ИЗМЕНЕНИЙ (Через CLI + Временный Буфер)

Из-за ограничений Go-бинарника jules на символы кириллицы и кавычки в путях macOS, запуск `jules remote pull` в рабочей папке выдает ошибку *"You must be in a git repository"*. 

**Процедура обхода (Временный Буфер):**
1. Склонировать чистый проект во временную папку без кириллицы:
   `git clone https://github.com/Gagarin-pro/monolith-verification-jules.git /Users/tur/monolith_temp`
2. Запустить накат изменений в этой временной папке:
   `cd /Users/tur/monolith_temp`
   `/Users/tur/.npm/_npx/76db0a0f29ffdc9b/node_modules/.bin/jules remote pull --session <SESSION_ID> --apply`
3. Выявить измененные файлы с помощью `git diff --name-only`.
4. Скопировать измененные файлы из временного буфера в рабочий проект на Google Диск.
5. Удалить или очистить временную папку `/Users/tur/monolith_temp`.
